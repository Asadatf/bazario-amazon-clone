## How we'll deploy

The order matters: the database comes first, then the API (the web app needs its URL), then the web app.

**1. Database on Neon (free, about 2 min)**

**2. API on Render (about 5 min)**
- In the Render dashboard, choose **New → Blueprint**, connect GitHub, and pick `bazario-amazon-clone`. It reads the `render.yaml` already in the repo.
- Set `DATABASE_URL` to the Neon string. Leave `WEB_ORIGINS` blank for now. The JWT and webhook secrets are generated automatically.
- Database migrations run when the API starts. When it's live, check `https://bazario-api-xxxx.onrender.com/api/v1/health`.
- Load the demo data once from your laptop:
  ```bash
  DATABASE_URL='<neon url>' ALLOW_SEED=true NODE_ENV=production npm --prefix api run db:seed
  ```

**3. Web on Vercel (about 3 min)**
- **Add New → Project**, import the repo, and set **Root Directory** to `web`.
- Set these environment variables:
  - `NEXT_PUBLIC_API_URL` to empty
  - `API_PROXY_TARGET` to `https://bazario-api-xxxx.onrender.com`
- This makes Vercel pass `/api/v1/*` calls through to Render. The login cookie then counts as Vercel's own, so Safari and Chrome don't block it as a third-party cookie and you stay logged in.
- Finally, go back to Render, set `WEB_ORIGINS=https://<your-app>.vercel.app`, and paste the two live links into the README.
